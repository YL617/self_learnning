> 阶段：**M5.5 · Learning Data Activation** ｜ 子阶段：**P4-3.2 人工审核体验（第一版，无前端）**
> 上游：`docs/M5.5_P4-3.1_AI题目生成管道设计.md`（G1–G8 门禁 + manifest 契约）
> 交付物：`scripts/p43_review_kit.py`、`backend/tests/test_p43_review_kit.py`
> 性质：**只读数据 + 本地文件读写**。零写库、零后端改动、零新依赖、零部署。

## 0. 结论摘要

### 0.1 一句话诊断

P4-3.1 把"生成"和"筛查"自动化了，但**瓶颈转移到了人**：50 道题要逐条读 JSON 才能审。
P4-3.2 的职责只有一句 —— **把人从 JSON 里解放出来，同时不牺牲审核的严格性**。

### 0.2 关键因果链

```
P4-3.1 产出 questions_manifest.json（含门禁结论）
        ↓ 人工现在必须逐条读 JSON → 审核疲劳 → 放水
P4-3.2 build：manifest → Excel 审核清单（就地可编辑 + 下拉判定 + 列保护）
        ↓ 人只做两件事：读题、点判定
P4-3.2 collect：清单 → 审核决定 JSON（含逐字段 diff / 推翻留痕 / 重跑结构门禁 / 最终查重）
        ↓
P4-3.3 Apply：按决定逐条建题 → submit_review → approve → publish（走 review_status 状态机）
```

**核心不变量**：`manifest` 永远是"原始内容"的唯一保管者；清单里那一份内容
由人工就地修改，`collect` 用它和 manifest 做逐字段 diff —— 因此**不需要"修订副本列"**，
人不必在两套列之间来回对照。

### 0.3 三个必须做 / 三个坚决不做

| 必须做 | 坚决不做 |
|---|---|
| 判定**只能四选一**，留空 = 未审核并一律阻断 | 不给"未审就入库"留任何口子 |
| 推翻门禁**必须写理由**，并记入 `overridden_gates` | 不让"通过"按钮静默绕过 G1–G8 |
| 修订后**重跑确定性结构门禁**（G1/G2/G5/G6） | 不假设"人改的一定对"（改选项忘改答案是最常见的手滑） |

### 0.4 工作量（本阶段实际发生）

| 项 | 量 |
|---|---|
| 脚本 | `scripts/p43_review_kit.py`（build + collect 两子命令） |
| 测试 | `backend/tests/test_p43_review_kit.py`，**31 例**，全部离线 |
| 新依赖 | **0**（`openpyxl>=3.1.0` 已在 `backend/requirements.txt`） |
| 后端 `app/**` 改动 | **0** |

## 1. 只读审计（本阶段实际读到的真实代码）

| # | 事实 | 影响 |
|---|---|---|
| 1 | `p43_gates.evaluate()` 是纯函数，可对**任意题面对象**重跑 G1–G7（`references=()` 时 G4 自动放行） | 修订后可原地复检，无需新写规则 |
| 2 | `p43_gates.gate_g4_duplicate(stem, references)` 接受任意参照集 | 可对"最终可入库内容"重跑最后一道查重 |
| 3 | manifest 每行已带 `quality_check.gates`（逐门禁 `passed` + `reason`）与 `suggested_action` | 审核清单可直接展示"哪条规则拦的"，不必回查日志 |
| 4 | manifest 的 `questions[].analysis` 存的是**原始解析**（未经 `_ensure_analysis` 补全） | 清单里展示/修改的就是将要写库的文本，无中间层 |
| 5 | `p43_gates.ANALYSIS_FILLER_FINGERPRINT` / `OFFLINE_FINGERPRINTS` / `BANNED_OPTION_PATTERNS` 均为模块级常量 | 复检与生成期判定**同源**，不会出现两套阈值 |
| 6 | 本地 `backend/.venv` 已装 `openpyxl 3.1.5` | 无需安装任何东西即可读写 xlsx |

### 1.1 为什么用 Excel 而不是前端

| 因素 | Excel 清单 | 新增 admin 审核页 |
|---|---|---|
| 落库前需要的东西 | 一个可离线审、可存档、可 diff 判定结果的载体 | 需要先部署才能用 |
| 前置依赖 | **无**（P4-3.0 部署前即可用） | 必须先部署（P4-3.0），且要先做前端 |
| 大批量体验 | 排序 / 筛选 / 冻结窗格 / 下拉，成熟 | 需自行实现 |
| 与"脚本驱动审核"的既定决策 | 一致 | 冲突 |

> 结论：第一版走 Excel。审核工作台（P4-4）留到有真实审核量、且前端已部署之后再评估。

## 2. 外部依据（增量，不重复 P4-3/P4-3.1）

| 来源 | 借到的点 | 本设计落点 |
|---|---|---|
| Duolingo **AQuAP + Item Factory**（自动筛查 → 人工评审两段式） | 人工评审必须拿到**结构化上下文**（题目 + 自动结论 + 建议），否则评审退化 | 清单并列展示"门禁结论 / 门禁原因 / 机械建议" |
| **KMLE 检查清单**（选项同质、避免"以上都对"） | 人审要点应当固化成清单，而非靠记忆 | `审核说明` 工作表内置 4 条"实际解题式"复核要点 |
| **HITL（human-in-the-loop）置信度路由** | 低置信/机器判错项应被**显式呈现**而不是过滤掉 | 门禁 FAIL 的题**保留在清单里**（不是剔除），只要求推翻时写理由 |
| **Redline / 变更留痕**（审阅工作流通用实践） | 审阅必须产生**可比对的差异**，而不是一份"最终稿" | `collect` 输出 `revision_diff`（字段级 before/after） |
| **AIR 经验教训**（提示再详尽也会产出不可用项） | 审核必须"可推翻但留痕"，且要有最终查重 | `overridden_gates` + 对最终内容重跑 G4 |

## 3. 方案设计

### 3.1 两段式工作流

```bash
# ① 构表（生成审核清单）
python scripts/p43_review_kit.py build \
    --manifest docs/M5.5_P4-3_题目供给清单_批1.json \
    --out      docs/M5.5_P4-3.2_审核清单_批1.xlsx

# ② 收表（回收审核决定）—— 人工在 Excel 里审完后执行
python scripts/p43_review_kit.py collect \
    --checklist docs/M5.5_P4-3.2_审核清单_批1.xlsx \
    --manifest  docs/M5.5_P4-3_题目供给清单_批1.json \
    --out       docs/M5.5_P4-3.2_审核决定_批1.json \
    [--existing docs/M5.5_P4-3_现有题面快照.json]
```

### 3.2 审核清单列布局（单表，就地编辑）

| 列 | 可编辑 | 说明 |
|---|---|---|
| 编号 | 🔒 | `question_id`（`P43-01-001`），全表的定位键 |
| 知识点 / 知识域代码 | 🔒 | 来自 manifest（`knowledge_point_name` / `_code`） |
| 门禁 | 🔒 | `PASS` / `FAIL`（PASS 绿字、FAIL 红字） |
| 门禁原因 | 🔒 | **带门禁代号**，如 `G3 解析原始长度 10 < 60` |
| 建议 | 🔒 | `suggested_action`（机械建议，人工可推翻） |
| 难度 | ✏️ | `easy/medium/hard`，允许人工重评 |
| 题干 | ✏️ | 就地改就是修订 |
| 选项A…选项N | ✏️ | 列数 = `max(4, 本批最大选项数)`，上限 6 |
| 答案 | ✏️ | |
| 解析 | ✏️ | |
| **判定** | ✏️ | 下拉四选一，浅黄底 |
| **审核备注** | ✏️ | 推翻门禁时的必填理由 |

- 冻结首行 + 首列（`freeze_panes="B2"`）、表头开启筛选（按 `门禁`/`判定` 过滤）。
- 锁定列由**工作表保护**兜住（无密码，纯护栏；`--no-lock` 可关）。
- 另两张表：`审核说明`（评审要点 + 规则说明）、`批信息`（批次溯源 + 生成失败清单 + 冻结阈值 + 门禁名对照）。

### 3.3 判定词表

| 显示 | key | 语义 | 允许有内容改动 | 门禁 FAIL 时 |
|---|---|---|---|---|
| 通过 | `approve` | 照原样入库 | ❌ | 需写备注 |
| 修改后通过 | `revise` | 就地改完再入库 | ✅（至少 1 处） | 需写备注 |
| 驳回 | `reject` | 不采用 | ❌ | — |
| 待定 | `defer` | 本轮不决定 | ❌ | — |
| *（留空）* | *`None`* | **未审核 → 阻断** | — | — |

### 3.4 校验规则（`collect` 的确定性判定）

| 码 | 级别 | 触发条件 |
|---|---|---|
| **E00** | error | 清单记录的 manifest SHA-256 ≠ 本次传入的 manifest |
| **E01** | error | 判定为空（未审核） |
| **E02** | error | 判定值不在四选一之内 |
| **E03** | error | 门禁 FAIL 的题点"通过/修改后通过"但审核备注为空 |
| **E04** | error | 判定"通过"但内容被改动（应改用"修改后通过"） |
| **E05** | error | 判定"修改后通过"但未改动任何字段 |
| **E06** | error | 修订后未通过**结构门禁** G1/G2/G5/G6 |
| **E07** | *warning* | 修订后 `G3`/`G4`/`G7` 提示，**以及任何门禁内部提示**（如 `G5` 长度均衡）（门槛不阻断，属审阅人裁量） |
| **E08** | error | 选项列存在中间空档（中间为空、后面还有内容） |
| **E09** | error | 判定"驳回/待定"但内容被改动 |
| **E10** | error | 编号不在本批 manifest 中 |
| **E11** | error | 编号重复 |
| **E12** | error | manifest 中的题未出现在清单里 |
| **E13** | error | 该行有内容但编号为空 |
| **E20** | error | **最终内容查重**：与现有题库或同批其他"可入库"题撞车（先到先得） |

> 只有 `error` 阻断（退出码 1）。`warning` 记入决定 JSON 供人工参考，不影响 `ready_for_apply`。

### 3.5 修订后重跑结构门禁（本阶段的关键防线）

修订后构造成题面对象，直接复用 `p43_gates.evaluate()`：

- **阻断**：`G1` 结构 / `G2` 答案可对齐 / **`G5` 选项合法性** / `G6` 元数据
  —— 这些是"改了一定坏"的规则。典型：改了选项却没同步答案 → `E06`。
- **仅提示**：`G3` 解析长度 / `G4`（修订场景不重复查重，交由 §3.6 统一做）/ `G7` 学科 /
  **`G5` 长度均衡**（P4-3.3.1：仅当"正确项显著长于干扰项"时出提示，见 `p43_gates.evaluate()` 的 `warnings`）。

> **P4-3.3.1 校准对审核体验的影响**：清单「门禁原因」列现在可能以 `提示：…` 开头（如"正确选项显著长于干扰项"）。
> 这类提示**不影响 PASS/FAIL**，也**不需要**在「审核备注」写推翻理由 —— 它只是让审阅人多看一眼。
> 批信息表另新增「选项洗牌 / 批内答案分布提示 / 仅提示待留意」三行便于一眼掌握批级状况。

### 3.6 最后一道门查重（相对 P4-3.1 的净增量）

P4-3.1 的查重发生在**生成时**（参照 = 现有题库 ∪ 同批在前的候选题）。
但人工修订可能让两道各自通过的题**在最终内容上撞车**。因此 `collect` 在收尾时：

> 对全部 `ready_for_apply` 的题，用**最终内容**重跑 `gate_g4_duplicate`，
> 参照集 = `--existing` 现有题库快照 ∪ **本次在前的可入库题**（先到先得）。

命中即 `E20`，并把该题踢出 `ready_for_apply`。

### 3.8 CLI 契约

| 子命令 | 参数 |
|---|---|
| `build` | `--manifest`（必填）、`--out`（必填）、`[--built-at]`、`[--no-lock]` |
| `collect` | `--checklist`（必填）、`--manifest`（必填，diff 基线）、`--out`（必填）、`[--existing]`、`[--collected-at]` |

| 退出码 | 含义 |
|---|---|
| `0` | 成功且无阻断问题 |
| `1` | 校验发现阻断问题（**仍写出决定 JSON**，供人工修正后重跑） |
| `2` | 用法错误 |
| `3` | 运行期失败（文件不可读 / manifest 非法 / 清单结构不符） |

### 3.9 幂等与可复现

- `build` 对同一 manifest **逐字节可复现**（已冻结 xlsx 的 `created/modified` 属性；测试断言字节相等）。
- `collect` 的判定是纯函数式：同一清单 + 同一 manifest → 同一决定（`collected_at` 除外）。
- 门槛阈值**不在本模块重复定义**：修订复检直接调用 `p43_gates` 的常量与函数。

## 5. 端到端冒烟（真实脚本 + 真实批1目标文件）

用**真实** `docs/M5.5_P4-3_生成目标_批1.json`（8 concept / 20 题）与**真实** `现有题面快照.json`，
合成"模型原始响应"留档后跑完整链路：

```
① 生成+门禁：候选=20  通过=20  拒绝=0  答案位置 {A:5,B:5,C:5,D:5}
② 构表：审核清单_批1.xlsx（3 张表，列保护：开）
③ 模拟人工：20 题判定「修改后通过」，其中 1 题故意把答案改成 F（改选项忘改答案）
④ 首轮 collect：可入库=19  阻断=1
     [ERROR] E06 P43-01-001：修订后未通过结构门禁 G2：答案字母 F 不在选项 ['A','B','C','D'] 内   → 退出码 1
⑤ 修正该行（答案还原 + 补一句解析）后重跑
⑥ 次轮 collect：可入库=20  阻断=0  提示=0  → 退出码 0
```

→ 证明：真实目标文件解析、清单生成、人工就地修订、结构门禁复检、最终查重、决定落盘全链路打通。
