## 0. 结论摘要

> P4-3.3 批 1 实跑暴露的真正问题**不是 AI 出题质量，而是门禁把"批级/风格属性"当成"单题缺陷"**。
> 本阶段只做一件事：**把门禁分成"阻断"与"提示"两级**，并把答案位置的不均衡从"逐题 FAIL"
> 改为"批级提示 + 生成阶段选项洗牌"（治本）。

| 项 | 校准前 | 校准后 |
|---|---|---|
| G5B 批内答案分布 | 逐题 FAIL → `suggested_action=reject` | **批级 advisory**（`warning{type,suggestion,message}`），不参与单题裁定 |
| G5 选项质量 | ①禁用表述 ②**全局长度极差比 ≤ 2.5** → 任一命中即 FAIL | ①合法性（禁用表述/空选项）**仍阻断**；②长度均衡**降级为提示**，触发条件改为"正确项显著长于干扰项" |
| 答案位置 | 由模型随机决定（实测 C=45%、D=0%） | **生成阶段确定性洗牌**，批内轮转分配 → 20 题恰为 A/B/C/D 各 5 |
| 单题结论 | PASS = 无 FAIL | 新增 `warnings`：PASS 但需人看 → `suggested_action=review` |

**批 1 复跑结果**：**20/20 通过、0 拒绝**（失败率 0% < 20% 目标），答案分布 5/5/5/5。

## 1. 触发：批 1 暴露的两个工程问题

### 1.1 G5B 的语义缺陷（责任错配 / 不自洽 / 与初衷相反）

原实现（`p43_gates.py` 旧 `evaluate_answer_distribution` + `assemble_manifest` 内的"责任落到越界字母"）：
批内某字母占比越界 → **该字母对应的每一道题**被单独标 `G5B FAIL` 且 `suggested_action=reject`。

批 1 实测：`{A:5, B:6, C:9, D:0}` → `offenders=['C']` → **9 道 C 题全部被判 FAIL**。三处问题：

| # | 问题 | 说明 |
|---|---|---|
| ① | **责任错配** | 真正的异常是"D 从未被使用"，却去惩罚 C 的题 |
| ② | **不自洽** | 删掉全部 C 题后，剩 9 题 A=44%/B=56% **依然**越界 —— 说明规则抓的不是"坏题" |
| ③ | **与初衷相反** | 题本身没有任何缺陷，却要人工逐条写 override 备注去推翻 |

→ 结论：**答案位置不均衡是"整批的统计属性"，不是任何单题的缺陷**。

### 1.2 G5 的阈值过敏

原规则②用"全部选项正文 `max/min ≤ 2.5`"。批 1 被它拦下的 3 题全是**定量短选项**：

| 题 | 选项 | 长度 | 极差比 | 实际质量 |
|---|---|---|---|---|
| P43-01-001 | `e / 2e / n+e / n²-e` | 1/2/3/5 | 5.00 | ✅ 正常题 |
| P43-01-008 | `i / n-i / n-i+1 / n-i-1` | 1/3/5/5 | 5.00 | ✅ 正常题 |
| P43-01-010 | `n/2 / n / (n+1)/2 / n-1` | 3/1/7/3 | 7.00 | ✅ 正常题 |

→ 数学/算法题里长度天然不齐；**长度差本身不是缺陷**。

## 3. 新的两级语义：`fail` vs `warning`

`evaluate()` 现在严格分离两条通道：

```python
reasons  = [r for gate in gates if gate.passed is False]          # 阻断：唯一能让题目不通过的东西
warnings = [r for gate in gates if gate.severity == "warning"]     # 提示：永不改变 passed
```

- 门禁结果新增 `severity` 字段：`"fail"` / `"warning"` / `None`。
- manifest 的 `quality_check` 增加 `warnings`；`gate_config` 增加 `blocking_rules` / `advisory_rules` 两个清单。
- `suggested_action` 三态：`reject`（有阻断）｜`review`（仅提示）｜`accept`（干净）。
- 审核清单的「门禁」列仍只由 `quality_check.passed` 决定；「门禁原因」列追加 `提示：…`（**不要求**人工写推翻备注）。

**原则**：**只有确定性缺陷可以阻断**。风格属性、批级统计属性一律只提示。

## 4. G5 拆分与优化规则

| 子规则 | 结论 | 判据 |
|---|---|---|
| ① **合法性** | **阻断**（`severity="fail"`） | 选项含「以上都/以上均/以上皆是/全选/全不选/都不对/都正确/全部正确」；或存在空选项正文 |
| ② **长度均衡** | **仅提示**（`severity="warning"`） | 见下 |

长度均衡的新判据（取代"全局极差比"）：

```
令 correct = 正确选项正文长度
    median  = 其余（干扰项）正文长度的中位数
触发提示 ⟺ correct ≥ 2.0 × median  ∧  correct > max(干扰项长度)  ∧  correct ≥ 6 字  ∧  干扰项 ≥ 2 个
```

- 阈值常量：`OPTION_ANSWER_LEAK_RATIO = 2.0`、`OPTION_ANSWER_LEAK_MIN_CHARS = 6`、`OPTION_ANSWER_LEAK_MIN_DISTRACTORS = 2`。
- 依据：AI 幻觉题最常见的"答案泄漏"形态是**正确答案因附带解释而明显更长**，而不是"选项长度不齐"。
- 批 1 实测：3 道被误判的题**全部**转化为 PASS（正确项分别为 2/5/3 字，未达 6 字门槛或未显著超中位数）；
  唯一保留提示的是 P43-01-016（正确项 40 字 vs 干扰项中位数 20 字，= 2.0× 且最长）。

## 6. 选项洗牌（治本）

### 6.1 算法

```
1. 规划批内槽位：plan_answer_positions(n)
   slots = [0,1,2,3,0,1,2,3,…]（长度 n）→ 用 sha256(seed+"answer-position-plan") 播种洗牌
   ⇒ 各字母出现次数差 ≤ 1（20 题 → 每字母恰好 5 次）
2. 逐题重排：shuffle_options(question, position=slot)
   · 干扰项用 sha256(seed + 题干) 播种洗牌
   · 把正确项放到第 slot 个位置
   · 选项统一重写为 "A. 正文"；答案字母 = 正确项的新位置
3. 答案以正文给出时，先按归一化正文匹配定位正确项；定位失败则只打乱顺序、原样保留答案（交给 G2 报错）
```

### 6.2 为什么不用"每题独立随机"

用户原始设想是"每 20 题天然 A≈5/B≈5/C≈5/D≈5"。实测**独立随机**在 20 题规模下并不保证：
第一次实现（独立随机）复跑得到 `{A:6, B:3, C:2, D:9}` —— **D 占 45%**，同样会被考生察觉。
故改为**整批轮转 + 洗牌**：既保留随机性（槽位分配被打乱、干扰项顺序被打乱），又保证批内均衡。

### 6.3 确定性（可重放契约）

- 种子全部来自 `hashlib.sha256`（**绝不用内置 `hash()`**，它受 `PYTHONHASHSEED` 影响）。
- 已验证：同一份原始留档重放两次，manifest 除 `generated_at` 外**逐字节相同**。
- manifest 记录 `options_shuffle: {enabled, algorithm, seed, applied}`，关闭时明确写 `enabled: false`。

## 7. 顺带修复：xlsx「逐字节可复现」契约

复跑时发现 P4-3.2 的既有测试 `test_build_is_byte_deterministic` **是潜在 flaky 的**（本阶段新增用例改变耗时后开始偶发失败）。定位到 **openpyxl 的两处时间依赖**：

| # | 依赖 | 现象 | 修法 |
|---|---|---|---|
| ① | zip 条目时间戳取**当前时间**（DOS 2 秒粒度） | 同一内容两次构建差 1 个字节（`...4c5d06...` vs `...4c5d07...`） | 重新打包时把条目时间戳钉死为 `1980-01-01` |
| ② | `save()` 时 openpyxl **无视** `properties.modified`、一律写当前时间（`created` 却受尊重） | `docProps/core.xml` 的 `dcterms:modified` 每次不同 | 重新打包时把 `dcterms:modified` 改回调用方设定值 |

→ 新增 `save_workbook(workbook, path)`：先在内存生成，再按固定时间戳重新打包。
**验证**：连续 80 轮双构建，字节差异 **0**。
审计意义：清单的 SHA-256 此后真正等价于「清单内容」，而不是「清单内容 + 构建时刻」。
