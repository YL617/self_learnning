# 破冰问卷功能设计

> 版本：V1.0（已确认）  
> 目标：在设计定稿前，把问卷的全面性、代表性、可答性、跳过机制、修改机制、形式多样性、数据合规全部考虑清楚。

## 1. 设计目标

破冰问卷服务于“冷启动”：

1. 让新用户在 1-2 分钟内完成注册后的第一次有效交互。
2. 用最少、最好答的问题收集足以生成第一份计划的信息。
3. 不让问卷成为门槛：允许跳过、稍后补填、随时修改。
4. 收集的信息必须有明确用途，每个问题都能映射到计划生成逻辑。
5. 遵守个人信息最小化原则，不收集与规划无关的信息。

## 2. 覆盖维度与问题映射

| 维度 | 用途 | 问题 |
| --- | --- | --- |
| 身份背景 | 匹配专业课程模板 | 专业、年级 |
| 学习目标 | 决定计划主题与优先级 | 近期目标 |
| 时间资源 | 决定任务量与时段 | 每周可学习时长 |
| 学习偏好 | 决定任务形式 | 喜欢的学习方式 |
| 薄弱环节 | 决定重点强化方向 | 学习痛点/薄弱点 |
| 能力基线 | 决定起步难度 | 摸底测试（可选，延后） |

## 3. 问题清单草案

### Q1 专业

- 题型：文本输入 + 联想建议
- 必答：否（跳过时默认“综合”）
- 可答性：用户直接输入自己的专业，常用专业提供快捷选项
- 说明：决定初始课程模板；不要求精确到方向

### Q2 年级

- 题型：单选
- 选项：大一 / 大二 / 大三 / 大四 / 研究生 / 其他
- 必答：否（默认“其他”）
- 说明：影响学习节奏与目标难度

### Q3 近期目标

- 题型：多选 + 自定义
- 选项：期末高分 / 通过四六级 / 掌握编程 / 考研 / 考证 / 留学 / 巩固基础 / 其他
- 必答：否（默认“巩固基础”）
- 说明：多选避免“只能选一个”的失真；自定义避免找不到自己的目标

### Q4 每周可学习时长

- 题型：单选区间
- 选项：少于 5 小时 / 5-10 小时 / 10-20 小时 / 20 小时以上 / 不确定
- 必答：否（默认 5-10 小时）
- 说明：用区间代替精确数字，降低回答成本；“不确定”是独立状态，提交时不传具体小时数，后端保留默认值

### Q5 喜欢的学习方式

- 题型：多选
- 选项：看视频 / 做题 / 读教材 / 混合学习 / 不清楚
- 必答：否（默认“混合学习”）
- 说明：决定计划里任务的表达形式，如“观看 20 分钟视频”或“完成 10 道练习”

### Q6 学习痛点 / 薄弱点

- 题型：多选（可选）
- 选项：计划难执行 / 知识点难懂 / 练习不够 / 时间不够 / 容易拖延 / 不清楚 / 没有明显痛点
- 必答：否
- 说明：用于调整计划难度与提醒频率；不填不影响出计划

### Q7 学校层次（可选，暂定保留）

- 题型：单选（可选）
- 选项：双一流 / 普通本科 / 高职 / 不方便回答
- 必答：否
- 说明：仅用于模板匹配，属于可选敏感信息，默认不强制

### Q8 可用时间段（可选）

- 题型：多选
- 选项：早上 / 下午 / 晚上 / 周末 / 不固定
- 必答：否
- 说明：用于后续“精力匹配”，MVP 可先采集不调度

> 决策点：Q7、Q8 是否进入 MVP，见文末待确认问题。

## 4. 全面性评估

覆盖了“学什么（专业/目标）、怎么学（偏好/薄弱点）、学多久（时间）、从哪开始（能力基线延后）”，满足生成第一份计划所需的最小信息集。

不追求“一次问全”：

- 能力摸底测试延后到 M3 之后，避免注册流程过长。
- 更细的兴趣、性格、作息不进入 MVP，避免过度收集。
- 每个字段都有默认值，保证信息缺失也能生成计划。

## 5. 代表性评估

问题选取遵循“直接影响计划生成结果”原则：

- 专业 + 年级 → 决定课程模板
- 目标 → 决定计划主题
- 每周时长 → 决定任务量
- 学习偏好 → 决定任务形式
- 痛点 → 决定优先强化点

与计划生成无关的信息（如性别、手机号、性格测试）一律不收集。

## 6. 可答性评估

- 全部问题提供选项，不要求用户回答开放长文本。
- 时间用区间，目标/偏好用多选，专业用联想输入。
- 每题都有“跳过”或“不清楚/不确定”选项。
- 预期完成时间：1-2 分钟。
- 避免“双盲问法”（如“你希望每天学多久”拆成区间而不是精确数字）。

## 7. 跳过机制

设计原则：问卷是引导，不是门槛。

1. 注册后进入问卷引导页，但页面提供“稍后填写”按钮。
2. 每道题独立可跳过，跳过项使用默认值。
3. 未完成问卷的用户仍可立即生成第一份计划（模板兜底）。
4. `user_profiles.onboarding_completed` 标记完成状态；未完成时在“我的”页显示补填入口。
5. 问卷进度可保存，下次从第一个未完成问题继续。

## 8. 修改机制

1. 问卷完成后，信息保存在 `user_profiles`。
2. “我的”页提供“完善学情/重新填写”入口，打开时回填已填内容。
3. 用户修改后调用 `PATCH /users/me/profile` 保存。
4. 修改信息不会自动覆盖已生成计划；前端提示“是否根据新信息重新生成计划？”，用户确认后才调用 `POST /plans/generate`。
5. 记录 `onboarding_completed_at`，便于审计。

## 9. 形式多样性

- 采用分步向导：每屏一个问题，顶部显示进度。
- 混合题型：联想输入（专业）、单选（年级）、多选（目标/偏好/痛点）、区间（时长）。
- 每一步都有“跳过此题”和“下次再说”。
- 完成按钮放在最后，避免中途误提交。
- Web 与小程序共用同一套问题和 API，交互分别适配。

## 10. 数据模型

`user_profiles` 扩展字段：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| school_level | str | null | 学校层次，可选 |
| pain_point | str | null | 学习痛点，JSON 数组或逗号分隔 |
| learning_style | str | null | 学习偏好，JSON 数组 |
| weekly_study_minutes | int | 420 | 每周可学习时长（分钟） |
| available_time_slots | str | null | 可用时间段，JSON 数组 |
| onboarding_completed | bool | false | 是否完成问卷 |
| onboarding_completed_at | datetime | null | 完成时间 |

> `daily_study_minutes` 继续保留，用于计划任务粒度；问卷的周时长可换算为每日默认值。

## 11. API 设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /users/me/onboarding | 获取当前问卷状态与已填数据 |
| POST | /onboarding | 保存问卷并标记完成；可顺带生成第一份计划 |
| PATCH | /users/me/profile | 后续修改学情 |
| POST | /plans/generate | 根据新信息重新生成计划（用户确认后调用） |

POST /onboarding 请求示例：

```json
{
  "major": "计算机科学与技术",
  "grade": "大二",
  "goals": ["通过四六级", "掌握数据结构"],
  "weekly_minutes": 840,
  "learning_style": ["看视频", "做题"],
  "pain_point": ["计划难执行"],
  "school_level": "普通本科",
  "generate_plan": true
}
```

响应返回保存后的画像 + 生成的计划（若 `generate_plan=true`）。

## 12. 前端交互流程

### Web

注册成功 → `/onboarding` 问卷向导 → 完成或跳过 → `/` 学习总览；  
“我的”页提供“完善学情”入口，回填已填内容。

### 小程序

“我的”页提供“破冰问卷/完善学情”入口；首次注册用户进入时显示引导提示。

## 13. 数据合规

- 只收集计划生成必需字段。
- 学校层次等敏感度较高字段设为可选，并提供“不方便回答”。
- 问卷页展示隐私政策链接。
- 数据导出与账号注销在 M1 后续补充，问卷数据一并覆盖。
- 不允许把问卷数据写入日志或提交到 GitHub。

## 14. 验收标准

1. 新用户注册后 1-2 分钟内可完成问卷。
2. 每一步都可跳过，跳过也能生成计划。
3. 完成或跳过后都能进入学习总览。
4. 已填信息可修改，修改后不会自动覆盖旧计划。
5. 无 API Key 时仍能通过专家模板生成第一份计划。
6. 问卷未完成时，“我的”页显示补填入口。
