# M4 设计方案（第二阶段）

> 基于《M4架构审计报告.md》的真实代码现状，最小侵入补齐管理员题库闭环。
> 原则：container 三条红线全部维持并升级到 DB 级；不重构、不删功能、不动稳定数据结构。

---

## 1. 设计总览

```
管理员 ──POST /admin/questions──▶ 共享题库(visibility='shared')
        ──POST /admin/questions/{id}/knowledge-points──▶ qkp（仅 concept，DB 约束）
        ──GET /admin/questions/{id} / GET /admin/knowledge-coverage──▶ 详情/覆盖

普通用户 ──GET /knowledge-points──▶ 浏览知识树（后端已有）
         ──GET /knowledge-points/{id}/questions──▶ 自己的题 + 共享题
         ──POST /questions/{id}/answers──▶ 判分（已有）
              └─ 同一事务：AnswerRecord + Mastery(concept-only) + 错题/复习（已有）
         ──GET /mastery──▶ 掌握情况（已有）
```

**复用优先**：答题、掌握度、错题复习、KP 绑定服务、判分、container 关口全部复用现有实现；M4 只新增"题库管理 + 共享可见性 + DB 约束 + 覆盖统计 + 前端页面"。

## 2. 数据库设计（migration `20261010_006_m4_question_bank`）

### 2.1 `questions` 加两列（nullable / 带默认，存量 8 行行为不变）

```sql
ALTER TABLE questions ADD COLUMN difficulty VARCHAR(16) NULL,
  ADD CONSTRAINT ck_questions_difficulty CHECK (difficulty IN ('easy','medium','hard'));
ALTER TABLE questions ADD COLUMN visibility VARCHAR(16) NOT NULL DEFAULT 'private',
  ADD CONSTRAINT ck_questions_visibility CHECK (visibility IN ('private','shared'));
```

- `difficulty`：管理员建题时显式指定；NULL → 沿用 `resolve_difficulty()` 题型映射（现行为）。
- `visibility`：`private`（默认，存量行为）/ `shared`（管理员共享题库题，全部登录用户可见可做）。

### 2.2 `knowledge_points` 加 UNIQUE + `question_knowledge_points` 复合外键（DB 级 container 禁令）

```sql
ALTER TABLE knowledge_points ADD CONSTRAINT uq_knowledge_points_id_node_type UNIQUE (id, node_type);
ALTER TABLE question_knowledge_points ADD COLUMN kp_node_type VARCHAR(16) NOT NULL DEFAULT 'concept',
  ADD CONSTRAINT ck_qkp_kp_node_type CHECK (kp_node_type IN ('container','concept')),
  ADD CONSTRAINT fk_qkp_kp_concept FOREIGN KEY (knowledge_point_id, kp_node_type)
    REFERENCES knowledge_points (id, node_type);
```

**语义**：qkp 行的 `(kp_id, 'concept')` 必须命中 knowledge_points 的 `(id, node_type)` → **DB 层物理拒绝 container 关联**（即使绕过服务层直接 INSERT 也被外键拦截）。qkp 当前 0 行，迁移零风险。
**副作用（正向）**：知识点 node_type 若被改为 container，已有关联会因 FK 阻断（RESTRICT 语义），恰好是"关联中的知识点不可降级为目录"的保护。

### 2.3 不做的变更（明确记录）

- `user_knowledge_point_mastery` 不加复合 FK：写入侧唯一来源是答题事务（KP 已过 qkp 关口），读取层已有 concept JOIN 防御；避免过度工程扩大回归面。
- 不建 `user_answer_records` / `knowledge_mastery` 新表：`answer_records` / `user_knowledge_point_mastery` 已存在且语义完备。
- 不建 QuestionTag：spec 未要求，`Question.knowledge_point` 文本列已承担旧语义。

### 2.4 可回滚性

downgrade 逐项逆操作：drop FK → drop CHECK → drop COLUMN(kp_node_type) → drop UNIQUE(id,node_type) → drop questions 两列及其 CHECK。

## 3. 后端模型 / Schema

- `Question`：+ `difficulty: Mapped[str | None]`（nullable）、`+ visibility: Mapped[str]`（default "private", server_default "private"）。
- `QuestionKnowledgePoint`：+ `kp_node_type: Mapped[str]`（default "concept", server_default "concept"）+ `ForeignKeyConstraint(["knowledge_point_id","kp_node_type"],["knowledge_points.id","knowledge_points.node_type"])`；服务层 attach 时写入该列。
- `KnowledgePoint.__table_args__`：+ `UniqueConstraint("id","node_type")`。
- Schema 新增（`schemas/admin.py`）：`AdminQuestionCreate`（subject/knowledge_point 文本/question_type/stem/options/answer/analysis/difficulty/visibility/knowledge_point_ids 可选）、`AdminQuestionDetailOut`（全字段 + 关联 KP 列表）、`KnowledgeCoverageOut`（总数/有题数/无题数/按学科明细）。
- `QuestionOut` / `AdminQuestionOut` 增补 `difficulty`、`visibility` 字段（增量字段，前端旧消费方不受影响）。

## 4. 服务层

- 复用 `QuestionKnowledgePointService.attach/replace`（container 拒绝、学科一致、primary 唯一、幂等——全部现成）；attach 路径补写 `kp_node_type='concept'`。
- `list_question_ids_for_knowledge_point` 语义扩展：owner 用户 → `Question.user_id == owner OR visibility == 'shared'`；admin → 全部。
- 新增 `KnowledgeCoverageService`（轻量，可直接在 admin 路由实现）：concept 总数、已关联题目数（distinct qkp）、未覆盖数，按学科分组。
- `submit_answer` / `list_questions` / `_resolve_question` 可见性规则：
  - 答题：`question.user_id == user.id OR question.visibility == 'shared'`（admin 亦全可）。
  - 用户题目列表（`GET /questions`）：自己的题（不变）+ 新增 `GET /question-bank?subject=&difficulty=`（shared 题库，无 owner 过滤）→ 前端浏览入口。
- MasteryService / evaluation / review / 错题：**零改动**（输入契约 EvaluationResult 不变；shared 题多用户作答按 (user, kp) 天然隔离）。

## 6. 前端设计

- **用户端新增** `KnowledgeExploreView.vue`（路由 `/knowledge`）：左侧知识树（container/concept 分层，GET /knowledge-points）→ 点 concept：详情 + 掌握度（GET /mastery/{id}）+ 关联题目（含共享题）→ 内嵌做题卡（提交 → 正确性 + 解析展示）。
- **管理端增强** `AdminQuestionsView.vue`：创建题目表单（题型/难度/可见性/KP 多选绑定，KP 选择器仅列 concept）、题目列表增列（难度/可见性/关联数）、覆盖统计卡（GET /admin/knowledge-coverage）。
- API client：`api/admin.ts`（createQuestion/getQuestion/coverage/attachKp）、`api/questions.ts`（questionBank）、`api/knowledgePoints.ts`（questions 含 shared）。
- 路由与导航菜单注册；非管理员访问 /admin 由现有 guard 拦截。

## 7. 测试设计（新增 `tests/test_m4_question_bank.py`，关键路径）

1. 权限：普通用户 POST/GET admin 题库接口 → 403；管理员 → 201/200。
2. container 拒绝：服务层 attach container → 400；**直接 INSERT qkp(container) → IntegrityError（DB 级复合 FK 生效）**。
3. visibility：shared 题其他用户可见可答（AnswerRecord + mastery 正确生成）；他人 private 题 → 404（回归保护）。
4. mastery：shared 题答对 → 分数上升、attempt+1；答错 → 下降 + 错题入册。
5. 隔离回归：kp 导入 preview/apply 行为不变（现有 test_knowledge_import / test_node_type_p0 全量通过）。
6. 覆盖统计：建题绑定后 covered/uncovered 计数正确。
7. migration：downgrade → upgrade 可回滚；schema 治理链路（freeze_schema_profiles 等）同步。
