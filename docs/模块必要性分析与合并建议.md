# 模块必要性分析与合并建议

> 统计日期：2026-08-27
> 依据：当前仓库代码（Web、移动端、后端路由与数据模型），不含规划中但未实现的功能。

## 1. 结论摘要

- “待办与日历”和“学习日历”是两个入口指向同一套数据的重复模块，已合并为单个“待办与日历”页面，内部用“待办 / 日历”分段切换。
- 学习总览、个人中心学习数据、学习周报存在统计数据展示重合，但用途不同，暂不强制合并，建议后续把学习周报并入学习总览。
- 待办、计划任务、提醒是三种“任务类”数据，语义有重合但结构不同，当前保留各自模型，不再新增同类任务模型。
- 智能练习 / 错题本、学习计划 / 对话规划、宠物 / 数字人、文件出题 / 公开课程属于互补而非重复，不建议合并。

| 模块 | 是否存在必要 | 结论 |
| --- | --- | --- |

| 学习计划 | 必要 | 平台核心“规划”闭环，保留 |
| 对话规划 | 必要 | 与计划列表互补，属于生成入口，保留 |
| 智能练习 | 必要 | 平台核心“练习”闭环，保留 |
| 错题本 | 必要 | 平台核心“反馈”闭环，保留 |
| 文件出题 | 必要 | 提供文档类内容来源，与练习互补，保留 |
| 专注模式 | 必要 | 学习行为追踪与番茄钟，保留 |
| 我的宠物 | 必要 | 游戏化激励，承载打卡与学习事件反馈，保留 |
| AI 数字人 | 必要 | 独立体验与会员价值，保留 |
| 待办与日历 | 必要 | 效能工具，本次已合并为单入口 |
| 提醒通知 | 必要 | 任务提醒与到期通知，保留 |
| 公开课程 | 必要 | 内容聚合与外链，保留 |

## 4. 重合与重复点

1. 待办与日历 / 学习日历：两个导航入口，一个待办页内还放了“打开日历”按钮，实际展示同一批待办与计划任务。属于直接重复，本次已合并。
2. 学习总览 / 个人中心学习数据 / 学习周报：三处都展示专注分钟、番茄钟数、计划数、答题数、智学币等统计。数据同源，只是粒度不同（今日 / 累计 / 近 7 天）。
3. 待办 / 计划任务 / 提醒：三种任务类数据结构。日历同时展示待办与计划任务，通知同时展示提醒与逾期计划任务，语义存在交叉，但模型用途不同，不建议简单合并。
4. 宠物 / 数字人：都提供 AI 聊天，但一个承担激励与宠物经济，一个承担数字人陪伴与会员体验，呈现和业务目标不同。
5. 账号设置 / 个人中心：账号资料与账号生命周期管理距离很近，当前分为两个页面。
6. 文件出题 / 公开课程：都是学习内容来源，但一个是用户文档出题，一个是外部课程索引，数据源不同。

## 5. 合并建议与优先级

| 优先级 | 建议 | 说明 |
| --- | --- | --- |
| P0 | 待办与日历合并为单页 | 已完成：`/todos` 为单入口，`/calendar` 自动跳转到日历分段 |
| P1 | 学习周报并入学习总览 | 保留 `/reports` 跳转兼容，总览内增加“周报”分段或卡片 |
| P1 | 账号设置并入个人中心 | 个人中心增加“数据导出 / 注销账号”区域，原入口可跳转或移除 |
| P2 | 统一任务中心 | 若后续产品需要，再把待办、计划任务、提醒统一呈现，但涉及数据模型决策，本次不做 |

## 6. 不建议合并的模块

- 智能练习与错题本：一个是做题入口，一个是错题沉淀，合并会破坏主流程。
- 学习计划与对话规划：列表管理 vs 生成流程，职责不同。
- 宠物与数字人：激励体验 vs 会员陪伴体验，目标不同。
- 文件出题与公开课程：用户文档 vs 外部课程，来源不同。
- 用户端与管理后台：权限与操作对象完全不同。

## 7. 本次执行结果

- Web 侧边栏只保留“待办与日历”一个入口。
- 旧 `/todos` 页面与 `/calendar` 页面合并为单页，内部保留原有全部功能。
- 未改后端接口、数据表与移动端。
