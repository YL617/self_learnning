## 3. 接口契约

`prefix = /api/knowledge-import`，**6 个接口全部 `Depends(get_current_admin)`**（复用既有权限模型，未引入新权限）。
所有接口**不落盘临时文件**：上传表格只在请求内解析进内存，请求结束即释放 → `apply` 必须重传数据（刻意取舍，避免引入文件生命周期与清理任务）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/preview` | 解析 + 校验 + 计划（dry-run）。**不写任何表、不建批次行、不落盘** |
| POST | `/apply` | 重新完整校验后单事务写入；支持 `expected_total_rows` 乐观锁 |
| GET | `/batches` | 分页列表（`status` 别名参数、`limit`≤200、`offset`） |
| GET | `/batches/{batch_id}` | 明细 + `blocking_references`（回滚阻塞预览）+ `notes` |
| POST | `/batches/{batch_id}/rollback` | 批次回滚 |
| GET | `/template` | CSV 模板下载（带 UTF-8 BOM） |

**错误响应**统一为结构化 `ImportRejection`，前端可直接渲染「哪一行错在哪」：

```json
{ "message": "...", "code": "E09",
  "batch_errors": [ { "row": null, "level": "error", "code": "B02", "message": "..." } ],
  "row_issues":   [ { "row": 7, "level": "error", "code": "E09", "field": "name", "message": "..." } ],
  "cycle": ["数据结构 > B", "数据结构 > A"] }
```

HTTP 映射：`ImportBatchNotFound`→**404**；`ImportCycleError`/`ImportConflictError`/`ImportWriteError`→**409**；其余解析类→**400**；超限→**413**。

## 5. 关键实现要点

### 5.1 不重复实现知识点写入逻辑（用户强约束）

service **不自己写任何 INSERT/UPDATE**，一律调用既有 `KnowledgePointService`：

- 新建 → `KnowledgePointService.create()`（M1 已扩展为接受 `code`/`aliases`/`difficulty`/`estimated_minutes`/`parent_id`）
- 更新 → `KnowledgePointService.update()`（按 `model_fields_set` 语义，天然表达「本次只想动这几个字段」）
- 命名清洗 → 复用 `clean_name()`；学科归一 → 复用 `normalize_subject()`
- 幂等键 `(normalized_subject, normalized_name)` 与 DB 唯一约束 `uq_knowledge_points_normalized_subject_name` **完全同源**

### 5.2 分隔符探测：弃用 `csv.Sniffer`

`csv.Sniffer` 在小样本下会给出离谱结论（曾把 `"学科,知识点名\n数据结构,栈,x,y,z"` 判成制表符分隔，导致 E11 永不触发）。
改为**4 个候选分隔符（`,` `\t` `;` `|`）逐一试切，按一致性取最优**：

```
score = (该列数出现的行数, 该列数, 是否等于扩展名默认分隔符)
```

一致性优先，因此不会被「某一列里恰好大量出现 `|`」骗到。

### 5.3 编码解码顺序不可颠倒

`utf-8-sig`（剥 BOM）→ `utf-8` → `gb18030`（兜底）。
`gb18030` 能「成功」解码几乎任意字节序列，**必须放最后**，否则会把 GBK 乱码吞成看似正常的中文。

### 5.4 openpyxl 的 5 个坑（均已规避）

| 坑 | 规避方式 |
|---|---|
| `read_only=True` 读不到合并单元格 | 接受该限制并在 `parse_notes` 中说明 |
| `max_row` 可能虚报 | 边迭代边计数，不信任 `max_row` |
| 必须显式关闭 | `try/finally: wb.close()` |
| `data_only=True` 对无缓存公式返回 `None` | 视为空单元格 |
| `.xls` 非 zip 格式 | 捕获 `BadZipFile` → 明确提示「请另存为 .xlsx」 |

### 5.5 父节点两趟创建的陷阱（实现期发现并修复的真实缺陷）

初版「先建父节点、再建子节点」两趟法会**留下空洞**：父节点本身可能就是本批某一行，此时它还没有 id。
修复方案：

1. `_creation_specs()` 把「自动父节点 + 待建行」合成**一张 id 待定表**；
2. 递归 `ensure(node)` 按需创建 —— **父级一定先于子级**；
3. 键统一用 `clean_name(segment)`（初版误用路径段原文，与 `node_for` 的键不一致 → 父节点查不到 → `parent_id` 为 `None`）；
4. **只有 `action == "create"` 才登记/创建父节点**（`skip`/`update_empty` 不建父，避免产生孤儿节点；但仍走完链以完成 E08 检查）。

### 5.6 回滚：先预检、后叶子到根删

`knowledge_points.parent_id` 是 `ON DELETE RESTRICT`，因此删除必须**从叶子到根**。`_delete_leaf_to_root()` 用 **Core DELETE**（绕开 ORM unit-of-work 的 FK 自动置空行为），按层批量删。

回滚前先跑 `collect_blockers()`，4 类引用任一命中即 **409 且零删除**：

| reason | 含义 |
|---|---|
| `has_children` | 本批节点被批次外节点当作父节点 |
| `linked_question` | 本批节点已被题目关联 |
| `has_mastery` | 本批节点已有掌握度记录 |
| `prerequisite_edge` | 本批节点已进入前置关系图（双向检查） |

### 6.1 ⚠️ 唯一实质偏差：D-M2-1「xlsx 拆成 M2b」

| 项 | 设计方案原建议 | 本轮实际执行 |
|---|---|---|
| D-M2-1 | ✅ **拆**（M2a 零依赖先落地，xlsx 隔离到 M2b） | ❌ **不拆**（用户明确要求「不要拆阶段，一次完成全部后端能力」） |

**后果**：必须**同时**修改两个依赖文件（这是 M2 唯一的「全项目共享」变更，必须作为显式验收项）：

| 文件 | 改动 | 为什么必须一起改 |
|---|---|---|
| `backend/requirements.txt` | `openpyxl>=3.1.0` | 声明依赖 |
| `backend/constraints-prod.lock` | `openpyxl==3.1.5` + `et-xmlfile==2.0.0` | `pip --constraint` **只约束出现在锁文件里的包**；且 CI 只执行 `pip install -r requirements-dev.txt`（即 `-c constraints-prod.lock -r requirements.txt`），**不在锁文件里的包在 CI 上根本装不上** |

**验收证据与关注点**：

- ✅ 本地已实测 `pip` 可达镜像、`openpyxl 3.1.5` / `et-xmlfile 2.0.0` 均可下载安装；实际导入验证：`openpyxl 3.1.5` + `et_xmlfile` 均 OK
- ✅ 锁定位置已核对：`constraints-prod.lock` 第 42 行 `et-xmlfile==2.0.0`、第 92 行 `openpyxl==3.1.5`（按字母序插入，未打乱既有条目）
- ✅ 选型为**纯 Python 包、无编译依赖**（`et-xmlfile` 是其唯一传递依赖），不引入编译工具链风险
- ⚠️ **CI 与生产部署时需关注**：镜像 label `xyz.yl617.ai-study.dependency-lock-sha256` 会**变化**（属预期），`production_release.sh` 会写入新的锁文件 sha256
- ⚠️ 本地 Windows dev venv 的 `pip check` 会报 5 条 `not supported on this platform`（`cffi`/`httptools`/`MarkupSafe`/`PyYAML`/`watchfiles`）—— **既有环境现象，与 openpyxl 无关**；CI 在 Linux 上执行，不受影响

### 6.2 实现期补充决策（设计方案未覆盖，本轮新增）

| 项 | 决策 | 理由 |
|---|---|---|
| **E11 列错位校验** | 新增 `column_overflow`（行内列数 > 表头列数 → 报错） | 用户在 Excel 里多敲一个逗号，会让后续列整体右移、`难度` 被当作 `预计学时` —— 静默写脏数据远比报错昂贵 |
| **skip/update_empty 行不新建父节点** | 只有 `create` 行才登记/创建父节点 | 否则会为「本就被跳过」的行创建出**没有任何子节点的孤儿父节点**；同时仍走完父链以完成 E08 跨学科检查 |

### 6.3 其余决策点落地情况

| 决策点 | 设计结论 | 落地情况 |
|---|---|---|
| D-M2-2 错误行策略 | `abort`（全有或全无） | ✅ 只实现 abort。有行级 error 时 `apply` 直接 **409**，不做部分写入 |
| D-M2-3 `conflict_strategy` 默认值 | `skip` | ✅ 接口签名默认值即 `skip`，`update_empty` 需主动选 |
| D-M2-4 回滚不还原 `update_empty` 填充字段 | 接受（换取零 DB 变更） | ✅ 接受；响应返回 `kept_updated_count`，批次明细 `notes` 显式提示该局限 |
| D-M2-5 `code` 列位置 | 追加末位（第 7 列） | ✅ 不破坏已有 1~6 位的文档约定 |
