## 0. 结论摘要

### 0.1 一句话诊断

> P4-3.1 交付的是**「生成 → 门禁 → 待审核清单」这三段里的后两段**：一个**离线、可重放、
> 零写库**的质量门禁与清单生成器。它不产生"好题"，它只负责把**确定性可判的坏题**
> 在人工审核之前挡掉，并把"模型这次到底吐了什么"变成可审计证据。

### 0.2 关键因果链

```
生产 documents = 0 / knowledge_chunks = 0
   └─▶ 出题无教材 grounding → 质量下限低（幻觉 / 多解 / 关键假设缺失）
        └─▶ 人工审核 = 唯一效度闸门 → 审核产能是瓶颈
             └─▶ 门禁的职责不是"判好坏"，而是"把确定性坏题挡在人工队列之前"
                  → 门禁必须确定性、可复现、可重放（本文档 §4.2 的 G1–G8）

question_generator.generate_questions()
   ├─ 只做精确 stem 去重           ─┐
   └─ _normalize() 里调用 _ensure_analysis()（<40 字解析自动补全）─┤
                                                                  └─▶ 两处都会削弱门禁
   ⇒ P4-3.1 **不复用它**：直连 AIModelGateway + 自带归一化（不补全）
```

### 0.3 三个必须做 / 三个坚决不做

| ✅ 必须做 | ⛔ 坚决不做 |
|---|---|
| 门禁写成**纯函数、零依赖**模块，可被 pytest 直载 | 不做：把生成放进生产容器（写操作 + 1.6 GiB OOM 风险） |
| `--live` 生成的**原始响应必须留档**，使每次生成可重放 | 不做：把离线降级响应当成"0 题正常结果"静默跳过 |
| 如实保留**原始** analysis 供 G3 判定（不调用 `_ensure_analysis`） | 不做：复用 `generate_questions()`（精确去重 + 解析补全双重削弱门禁） |

## 3. 第三步：方案设计

### 3.1 管道形态（三段式，零后端改动、零写库）

```
┌─ A1 生成（离线）──────────────────────────────────────────────────┐
│  --live：逐 concept 调 AIModelGateway.chat(SYSTEM_PROMPT + 难度要求) │
│          原始响应**必须**留档到 --raw-dir/<序>.json（可重放）        │
│  或 --raw-dir（重放）：直接读留档，**零网络**                        │
└──────────────────────────────┬─────────────────────────────────────┘
                               ▼
┌─ A2 门禁（纯函数，确定性）─────────────────────────────────────────┐
│  normalize_candidates()：镜像 _normalize **但不做解析补全**          │
│  （P4-3.3.1）选项洗牌 shuffle_entries()：批内均衡分配答案槽位        │
│  G1 结构 → G2 答案对齐 → G3 原始解析 → G4 去重 → G5 选项（合法性阻断 │
│  / 长度均衡提示）→ G6 元数据 → G7 学科 → G8 离线降级；批级 G5B 仅提示 │
│  产出：questions_manifest.json（每题带 gate 明细 + warnings + action）│
└──────────────────────────────┬─────────────────────────────────────┘
                               ▼
┌─ A3 人工清单审核【停点】────────────────────────────────────────────┐
│  P4-3.2：逐条 accept / reject / edit（**下一步，本阶段不做**）        │
└─────────────────────────────────────────────────────────────────────┘
```

**关键设计选择**

| 选择 | 理由 |
|---|---|
| 双模（`--live` / `--raw-dir`），**必须显式指定** | 绝不隐式联网；离线环境与 CI 只能走重放 |
| `--live` 强制 `--raw-dir` | 每次真实生成都可重放 → "模型到底吐了什么"成为审计证据 |
| 自有归一化，不调 `_ensure_analysis()` | G3 必须看到模型原样输出；补全会掩盖低质解析 |
| 复用 `extract_json()` | 重放与线上**同一解析器**，避免语义漂移 |
| 门禁模块不含 app 依赖 | 可被 pytest 直载（同 `test_deployment_flow.py` 先例） |
| 参照标签：同批用 `question_id`，现有题库用 `existing:<id>` | 人工可在 manifest 内直接定位重复对象 |

### 3.2 门禁规格 G1–G8（**已冻结进 manifest 的 `gate_config`**）

| ID | 规则 | 阈值 | 依据 | 预期命中 |
|---|---|---|---|---|
| **G1** | 结构：`stem` 12–400 字；`answer` 非空；题型 ∈ {choice, fill, short_answer}；choice → `2 ≤ options ≤ 6` | 见左 | 现 schema 上限 | 低 |
| **G2** | **答案可对齐**：choice → `answer` 首字母 ∈ 选项首字母集合 | 严格 | KMLE 单一可辩护答案 | 中 |
| **G3** | **解析原始质量**：**原始** `analysis` ≥ 60 字，且不含补全指纹「复习提示：请结合」；若解析明确声明“正确答案为/是 X”，必须与结构化 `answer` 一致；**指纹优先于长度判定** | 60 字 | 复用 prompt 自述要求 + 防补全掩盖 + 防解析答案冲突 | 中 |
| **G4** | **两级去重**：① 归一化（NFKC + 小写 + 去空白标点）后精确比对；② 字符 3-gram Jaccard ≥ 0.80。参照范围 = 现有题库快照 ∪ **同批在前**的候选题 | 0.80 | KMLE n-gram 去重；AIR redundant items | **高**（现有代码零防护） |
| **G5** | **选项质量（两级）**：① **合法性（阻断）** 禁用「以上都/以上均/以上皆是/全选/全不选/都不对/都正确/全部正确」、空选项；② **长度均衡（仅提示）** 正确项 ≥ 2.0× 干扰项长度中位数 ∧ 严格最长 ∧ ≥6 字 | 见左 | KMLE 选项同质；**P4-3.3.1 校准**：全局极差比 ≤2.5 对定量短选项过敏，已废除 | 中 |
| **G5B** | **批内答案位置分布（批级 advisory，P4-3.3.1）**：占比 ∈ [20%,30%]、用满 ≥4 字母、样本 ≥20 —— 仅用于生成**提示文案**，**不参与任何单题裁定** | 见左 | KMLE 答案位置偏差；**教训**：批级属性不能当单题缺陷 | 中 |
| **G6** | **元数据**：`knowledge_point` 文本 = 本批目标 concept 名（**非章名**）；`difficulty` ∈ {easy, medium, hard} 且非 NULL | 严格 | 修正现存值全为「栈和队列」；全项目唯一难度词表 | 低 |
| **G7** | 学科一致（`subject` 与本批学科一致）；**节点类型恒 concept 由 Apply 阶段的 `attach()` 保证** | 严格 | M4 既有关口 | **预期 0** |
| **G8** | **离线降级判定**：原始响应含「离线降级响应」/「配置模型 API Key」指纹、为空、无法解析为 JSON、或解析后 0 题 → 一律记 `error` | 严格 | `AIModelGateway` 两条静默降级 | 视网络 |

**两级语义（P4-3.3.1 校准）**

- **阻断**（`severity="fail"`，唯一能让题目不通过的东西）：G1 结构 / G2 答案对齐 / G3 原始解析 / G4 重复 / G5① 选项合法性 / G6 元数据 / G7 学科 / G8 离线降级。
- **提示**（`severity="warning"`，永不改变 `passed`）：G5② 答案泄漏（正确项显著更长）、G5B 批级答案分布不均衡。
- `suggested_action` 三态：`reject`（有阻断）｜`review`（仅提示）｜`accept`（干净）。

> ⚠️ **G5B 的语义已在校准中改写**。旧实现把"占比越界的字母"对应的题逐条判 FAIL 并置
> `suggested_action=reject` —— 这在批 1 实测中把 9 道**本身无缺陷**的 C 题全部拒掉（责任错配、
> 不自洽、与初衷相反）。现改为**纯批级 advisory**：只产出
> `warning{type:"answer_distribution", suggestion:"shuffle_options", message}`，
> 并配合**生成阶段选项洗牌**（算法与公式见 `docs/M5.5_P4-3.3.1_门禁校准设计.md` §6）从源头让答案字母均匀。

> 📌 **G3 / G4 是本阶段相对现有代码的净增量**（`generate_questions()` 既不看原始解析长度，也只做精确去重）。
