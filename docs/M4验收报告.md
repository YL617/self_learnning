## 1. 目标与结论

M4 目标是建立「题目 → 知识点 → 掌握情况 → 学习反馈」最小完整闭环。经第一阶段架构审计确认，底层能力（Question/QKP/AnswerRecord/Mastery/WrongBook 五表、答题单事务闭环、mastery 仅 concept、推荐排 container）已具备约 80%，真正缺口为：

1. 管理员题库能力（创建/详情/绑定/覆盖统计）
2. 共享题库可见性模型（此前题目全部私有，用户只能练自己 AI 生成的题）
3. DB 级 container 禁令（此前仅服务层拦截，绕过服务层直插 container 关联不会被拒绝）

以上三项缺口全部落地，闭环打通：**管理员建题（绑 concept）→ 全员在知识图谱页做题 → 后端事务内更新 mastery → 前端掌握度可视化反馈**。

## 3. 后端实现

- **模型**：Question +difficulty/visibility（含 CheckConstraint）；QuestionKnowledgePoint +kp_node_type + 复合 FK + CHECK；KnowledgePoint + UNIQUE。
- **Schema**（schemas/admin.py）：AdminQuestionCreate（subject/knowledge_point/question_type/stem/options/answer/analysis/difficulty/visibility/knowledge_point_ids）、AdminQuestionDetailOut（全字段+关联）、AdminQuestionKnowledgePointAttach、KnowledgeCoverageItem/Out；question.py 的 QuestionOut/AdminQuestionOut 增 difficulty/visibility。
- **Service**（question_knowledge_point_service.py）：`list_question_ids_for_knowledge_point` 增 `include_shared` 参数（普通用户可见 shared + 自己私题，他人私题 404）；attach/replace 显式写 `kp_node_type='concept'`。
- **难度解析**：`resolve_difficulty()` 显式 difficulty 优先，否则按题型映射——加列即生效，零代码改动兼容历史数据。

## 4. API 变化

| 方法/路径 | 权限 | 说明 |
|---|---|---|
| `POST /api/v1/admin/questions` | admin | 创建题目（默认 shared），可选 knowledge_point_ids 一并绑定（仅 concept，第一个 primary）；单事务，container 拒绝时整体回滚（400） |
| `GET /api/v1/admin/questions/{id}` | admin | 详情（全字段含 answer/analysis + 结构化关联） |
| `POST /api/v1/admin/questions/{id}/knowledge-points` | admin | 绑定知识点（与用户端同一服务关口：container 一律 400） |
| `GET /api/v1/admin/knowledge-coverage` | admin | 覆盖统计：concept_total/covered/uncovered/question_total + 按学科 items（**只统计 concept，container 永不计入**） |
| `GET /api/v1/question-bank` | 登录用户 | 共享题库列表（仅 visibility='shared'），支持 subject/difficulty/knowledge_point_id/limit 过滤 |
| `GET /api/v1/knowledge-points/{id}/questions` | 登录用户 | 语义增强：返回 shared + 自己私题（他人私题不可见） |
| `POST /api/v1/questions/{id}/answers` | 登录用户 | 语义增强：可作答 owner OR admin OR shared 的题目；他人私题 404 |

既有端点零破坏：所有旧行为（私题默认、AI 生成、错题本、掌握度算法）不变。
