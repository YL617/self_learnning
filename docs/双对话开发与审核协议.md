## 每轮流程

1. 从已批准规划中选择依赖已满足的任务，明确任务 ID、范围和验收标准。
2. 实施方完成任务，发送成果包：基线 commit、准确文件清单、diff、验证命令与结果、遗留问题、未验证事项。
3. 审核方独立核验证据，输出 PASS、PASS WITH CHANGES 或 BLOCKED，并将反馈直接发送实施对话。实施方读取审核对话结果亦视为有效回传。
4. 未通过则修改并以新版本再次送审；PASS WITH CHANGES 中的必要修改完成前不能关闭任务。
5. 通过后审核方给出下一任务提示词，包含目标、范围、验收标准、依赖与阶段限制；实施方核对用户授权后执行。
6. 同一任务同一成果版本只发一次；没有新成果或新证据时不互相触发。重复失败时先重新诊断，不能无限重试或降低验收标准。

## 全部计划的范围

以 V9 架构、已经采纳且不冲突的 V8 功能、后续用户批准的变更为依据。归并重复任务，记录已完成、进行中、待执行、外部阻塞、已取消和待决策状态。旧文档中的设想不能自动成为已批准需求，阶段编号冲突按交付物名称核对。

每项任务需记录来源、依赖、完成证据与验收结论。全部完成必须逐项有证据，不能以功能存在、测试通过或双 AI 一致代替产品效果验收。

## 真实性与执行边界

- AI 内容复核只能标记为 AI 复核；不能填写虚假的真人审核者、签字或责任确认。
- 既有明确生产门禁继续有效。自主循环不等于授权所有生产写入、破坏性操作、付费或凭据使用。
- 结构化测试不能证明题目内容正确，必须保留原始生成内容、修订差异和审核依据。
- 不纳入无关未跟踪文件，不使用 `git add .`，提交说明使用中文。
- 当前对话结束、运行环境退出或权限阻断时不能声称仍在后台持续运行。恢复时从最后一个有证据的检查点继续。
