## 9. 本次部署处置的两个阻断问题

### 9.1 构建阻断：阿里云 PyPI 镜像 metadata 404（已修复 `08272ed`）

`pip` 下载 `cryptography-50.0.1` 的 PEP 658 `.whl.metadata` 被阿里云镜像 404（wheel 本体 200）；清华/腾讯同样 404；官方 PyPI 从服务器仅 12.6KB/s。**华为云 `repo.huaweicloud.com` 全链路 200 且 index 0.076s**，遂把 `backend/Dockerfile` 的 pip 索引源切换为华为云。仅换索引源，`constraints-prod.lock` 与依赖版本零变更。

### 9.2 红线缺口 + 治理不变式死锁（已修复 `f65e88e`）

- **缺口**：006 的复合外键只校验 `(id, node_type)` 对存在性，而 `ck_qkp_kp_node_type` 词表为 `IN ('container','concept')`，故显式写 `kp_node_type='container'` 的裸 SQL 可绕过防线。→ 007 将 CHECK 收紧为 `kp_node_type = 'concept'`。
- **连带发现**：冻结合同不追踪 CHECK 约束，导致 007 与 006 的结构快照逐字节相同，触发 adoption 的「恰好一个可信结构匹配」不变式 → 实测 `ADOPTION BLOCKED: Expected one trusted schema match; got ['20261010_006','20261010_007']`，会同时打挂 CI 与发布 preflight。→ 修正 `adoption_inspector`：在结构等价的多个 revision 中取链上最新匹配；**零匹配仍阻断、落后版本/版本不一致仍阻断**，历史 9 份合同哈希逐字节零变更（已用 `diff` 验证）。
